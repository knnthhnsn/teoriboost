## Visual tokens

- `site.css:3-14`: local Rubik variable display (`300–900`) and Atkinson body (`400`, `700`); `--yellow:#FFD60A`, `--ink:#1F2328`, `--ink-2:#2B3138`, `--white:#FEFFED`, `--mist:#F4F5F7`, `--line:#E3E5E8`, `--muted:#5F656D`; home gutter `clamp(16px,4vw,56px)`, content width up to 1320px, header 76px. `knowledge.css:1-3` uses the same local fonts and core colors; its header is 80px desktop and 68px at 520px.
- `site.css:23-36,63-82,85-103`: Atkinson body 18px/1.55; Rubik headings 800; visible 3px focus; 44px link/button target convention; rounded yellow/ink buttons with a circular chevron. Brand dot is yellow. `knowledge.css` uses the analogous `.action` button and `.link-chevron-disc` pattern.
- The brief's color list is broader than the legacy guide gate's approved UI hex set. New directory CSS must honor `BRIEF.md` colors, while gate reuse needs to account for its narrower allowlist.
- Avoid copying `knowledge.css` body declaration blindly: its body rule contains `background:var(--#FEFFED)`, an invalid custom-property reference. Prefer an explicit `var(--paper)`/`var(--white)` in directory CSS.

## SEO and content gates

- The build script `../natkoersel/scripts/build-seo.mjs:1-40` reads explicit article catalogs and question map, rejects duplicate/invalid slugs, renders the hub/articles, sitemap and permissive `robots.txt`. It writes into `../natkoersel/site`, its authoring manifest and analytics path list; do not run it for this workspace.
- `validate-seo.mjs:9-25,209-268,863-910,929-1135` is coupled to those source catalogs and required `/viden/` slugs. Its reusable rules: unique nonempty title/description/canonical/H1; valid canonical and `og:url` parity; no noindex/third-party scripts; local asset, link and fragment resolution; Article and Breadcrumb JSON-LD consistency; visible source links/date; source dates not in the future; visible inbound internal links; sitemap/canonical parity and crawlable robots. It writes reports in `../natkoersel/evidence/seo-2026-10-30/`, even with `--site-root`, so stage or adapt it inside this workspace rather than invoking it on the sibling tree.
- `check-guide-design.mjs:7-16,135-160,463-520,562-593,602-733` checks visible zero-padded ordinals, decorative arrow glyphs, one-sided card border bars, off-palette manual hex and duplicate TOC numbers. The existing CLI scans `/viden/` and linked CSS only, so its PASS does **not** validate `/koereskoler/`. Extend/adapt the scope in a workspace copy for the new section, and use the brief's broader allowed colors where appropriate.
- A safe read-only baseline command is `node ../natkoersel/scripts/check-guide-design.mjs --site-root <absolute path to ../teoriboost-release-site-perf-20261108>`, omitting `--report`. It returned `PASS`, 312 guides + one hub, zero violations and zero errors on 2026-11-10. For directory output, a report path must stay under this workspace, such as `qa/design-validation.json`.
- `robots.txt:1-4` allows all and points to `https://teoriboost.dk/sitemap.xml`. The supplied root sitemap already contains `/viden/teori-app-eller-koereskole/` (line 8), `/viden/selvstudie-koereteori/` (line 21), `/viden/hvor-mange-koeretimer/` (line 25), and `/viden/pris-koerekort/` (line 29). Their local `index.html` files exist. `/viden/koereskoler/` does not exist. Directory pages need their own `site/koereskoler/sitemap.xml` for later merger into the root sitemap, as the brief says.

The brief also requires sourced business facts, per-field provenance, route-specific visible text, near-duplicate detection, schema types that exist, no fabricated prices/reviews/pass rates, source and correction information, keyboard use, 44px targets, contrast, reduced motion, and 320–1440px screenshots. The existing guide check alone does not cover those requirements.
